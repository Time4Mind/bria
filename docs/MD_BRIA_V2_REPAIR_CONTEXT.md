# Контекст для агента MD: восстановление Bria v2 на корпоративном Mac

Нужно полностью восстановить Bria v2 на корпоративном Mac. Внешний исполнитель не имеет доступа к этому железу, поэтому все действия выполняются локально на целевом устройстве и безопасно.

## Экземпляр

- LaunchAgent: `gui/501/com.time4mind.bria.v2`
- Бинарник: `/Users/a-s-nosko/.local/opt/bria-v2/current/bria`
- Команда запуска: `bria run --config /Users/a-s-nosko/.bria-v2/config.json`
- Рабочая директория: `/Users/a-s-nosko/.bria-v2`
- Лог: `/Users/a-s-nosko/.bria-v2/logs/bria.log`
- Состояние: `/Users/a-s-nosko/.bria-v2/state.json`

## Симптом

LaunchAgent запускается, но процесс завершается с кодом `1`.

Ошибки запуска:

1. `open Bria settings: validate settings JSON: missing field "revision"`
2. `recover persisted sessions: persist recovery failure: validate next session: created at is required`
3. Дополнительно встречаются `persisted value mismatch` и `outbound delivery is unknown for operation ...`; их нужно проверить как вторичные последствия несовместимого состояния.

## Диагноз

Сохранённые settings/session state относятся к старой схеме и не проходят строгую валидацию текущего бинарника.

Удаление основного `config.json` не является решением: Bria не создаёт его автоматически.

## План восстановления

1. Остановить LaunchAgent и сделать резервную копию всего `/Users/a-s-nosko/.bria-v2` с ограниченными правами.
2. Не выводить и не изменять Telegram token, callback key, provider credentials и другие приватные данные.
3. Проверить текущий `config.json`; не удалять и не пересоздавать его вслепую.
4. Безопасно мигрировать settings:
   - добавить корректный положительный `revision`;
   - сохранить существующие пользовательские настройки;
   - провалидировать итоговый JSON.
5. Найти сессии без `created_at`:
   - если запись восстановима — заполнить значение из доступного timestamp (`created`, `state_changed` или `last_resumed`) по документированному правилу;
   - если запись действительно повреждена и восстановление невозможно — удалить только эту запись из durable state, не удаляя весь state.
6. Проверить checkpoint/outbound receipts и исправить только действительно несовместимые записи.
7. Запустить Bria через LaunchAgent.
8. Проверить:
   - процесс остаётся активным;
   - LaunchAgent не уходит в цикл перезапусков;
   - `/status` и меню отвечают;
   - существующие сессии открываются;
   - новые запросы принимаются;
   - Telegram/provider secrets не попали в логи.
9. Все изменения state выполнять атомарно и с возможностью отката.

## Отчёт

Указать:

- где создана резервная копия;
- какие типы записей были мигрированы или удалены;
- результат запуска и проверки LaunchAgent;
- оставшиеся проблемы.

Не показывать секреты и полные приватные payloads.
