# Tier 1: препроцессинг пользовательского запроса

Статус: **согласовано владельцем 2026-09-10**. Препроцессинг реализуется
постоянными скрытыми сателлитами; внешний Telegram-сценарий остаётся отдельной
границей приёмки.

## Пользовательский flow

| Шаг | Согласованное поведение |
|---|---|
| 1. Приём | По умолчанию выбран режим `Общий`. После приёма текстового запроса карточка показывает исходный текст как `🙋‍♂`. Для голоса сначала виден этап распознавания, затем исходная расшифровка Parakeet как `🙋‍♂`. |
| 2. Обработка | В режиме `Общий` запросы всех основных сессий последовательно получает один постоянный скрытый сателлит. В режиме `На сессию` каждая основная сессия использует свой постоянный сателлит. Основная модель получает только уже подготовленный запрос. |
| 3. Успех | Та же запись карточки заменяется на `🙋‍♂ <очищенный текст>`. После точного подтверждения основной модели она становится `👨‍💻 <очищенный текст>`. Отдельного сообщения об успехе нет. |
| 4. Ошибка | Карточка показывает `❌ Ошибка препроцессинга`, следом исходный запрос. Исходный запрос сразу идёт основной модели; после подтверждения сохраняется строка ошибки и статус запроса меняется на `👨‍💻`. Ошибка препроцессинга никогда не блокирует коммуникацию. |

## Изоляция и выбор модели

| Правило | Реализация версии 1 |
|---|---|
| Контекст | Сателлит сохраняет свою историю между запросами. `Общий` использует один контекст для всех основных сессий; `На сессию` изолирует контекст по основной сессии. История основной модели в сателлит автоматически не копируется. |
| Возможности | Отдельный `bria-codex-adapter` process group держит persistent Codex thread с read-only sandbox, без shell/browser/app tools и запросов подтверждения. Технический thread и его binding не показываются в каталогах Bria. |
| Выбор | На локальной ноде используется постоянный Codex thread с `gpt-5.6-luna`. Stateless provider не подменяет сателлит: если persistent read-only thread недоступен, препроцессинг фиксирует ошибку и основная сессия получает исходный запрос. |
| Режимы | `Выключен` не создаёт и не использует сателлиты. `Общий` держит один сателлит до shutdown Bria. `На сессию` держит один сателлит всё время жизни каждой основной сессии. |
| Lifecycle | Close - операция остановки. Её durable итог archive закрывает процесс персонального сателлита и сохраняет его thread identity. Restore основной сессии возобновляет тот же персональный satellite. Общий satellite от lifecycle отдельных сессий не зависит. |
| Сброс | Изменение provider-настроек или режима закрывает больше не используемые процессы. Durable binding и desired state позволяют идемпотентно восстановить нужные сателлиты после restart. |

Один пользовательский запрос создаёт не более одного LLM-вызова
препроцессинга. Повтор lease до durable acceptance получает уже рассчитанный
результат. После двух живых timeout при лимите 5 секунд (medium и low)
пилотный предел 2026-09-06 увеличен до 10 секунд, reasoning явно low.
Это не измеренные p50/p95 и не утверждение о гарантированной задержке.
App-server принимает явный запрос `model=gpt-5.6-luna`, но не возвращает
независимый receipt фактически тарифицированной модели. Поэтому поле `model`
в lifecycle означает requested model, а `model_evidence` остаётся пустым.
Успех и cache/fallback журналируются отдельно без исходных текстов.

## Команды, вложения и размер

| Случай | Поведение |
|---|---|
| Slash-команда | Команда без аргументов либо с 1–3 аргументами обходит препроцессинг. При 4 и более аргументах текст обрабатывается обычно. |
| Вложения | Бинарное вложение и его custody не меняются; переписывается только текст или подпись. Вложения не считаются аргументами slash-команды. |
| Результат | Принимается только непустой валидный UTF-8 текст без NUL. Tools/структурированные ответы и превышение пропорционального лимита считаются ошибкой с fallback на исходник. |
| Инструкция | Пустое пользовательское значение означает встроенную инструкцию. Пользовательская инструкция полностью заменяет встроенную; общие ограничения изоляции сохраняются. |

Пилотный предел результата: не более максимума из тройного размера исходника
и размера исходника плюс 1024 байта, с техническим потолком 1 MiB. Формула
может быть скорректирована по фактическим запросам без изменения flow.

## Надёжность и наблюдаемость

| Правило | Поведение |
|---|---|
| Порядок | Каждый сателлит имеет одного FIFO owner протокола. Следующий запрос начинает model turn только после durable acceptance результата предыдущего; разные персональные сателлиты могут работать параллельно. |
| Crash до обработки | Журнал хранит исходник, инструкцию и выбранный режим; незавершённый элемент повторяется после восстановления lease. Старый envelope без режима детерминированно означает `Общий`. Режим кодируется в совместимой v1-форме инструкции, поэтому предыдущая strict-сборка может прочитать pending envelope при rollback. |
| Crash после обработки | Выбранный очищенный текст либо решение использовать исходник записывается в тот же журнальный элемент до передачи основной модели. Повторный запуск не вызывает препроцессор заново и не создаёт второй submit основной модели. |
| Смена настройки | Влияет на сообщения, принятые после изменения. Уже принятый элемент заканчивает зафиксированный flow; manager переключает admission generation и не направляет новые запросы в старый режим. |
| Ошибка | Safe-log получает `prompt.preprocessing_failed` и безопасные lifecycle-события start/ready/respond/accept/archive/restore/close без исходного пользовательского текста. Startup и close имеют bounded cancel/kill/wait. |

Расходы препроцессора входят в обычную квоту Codex и поэтому
естественно отражаются в экране `Статус` при следующем обновлении квот.

## Видимость

Сателлит не является `domain.Session`: у него нет отдельной карточки, кнопки,
строки в активных сессиях или архиве. Пользователь управляет только режимом
препроцессинга; lifecycle персонального сателлита следует за основной сессией.
