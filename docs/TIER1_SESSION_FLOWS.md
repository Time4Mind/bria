# Tier 1: ноды и автоматически открытая сессия

Статус: нодовый flow направления 1 согласован; реализация направления 2
повторно прямо запрошена владельцем 2026-09-06, отдельно включается и по
умолчанию выключена. Детали выбранной реализации зафиксированы ниже.
Документ детализирует основной продуктовый контракт для этих двух направлений.

Согласованный flow препроцессинга вынесен отдельно в
[`TIER1_PREPROCESSING_FLOW.md`](TIER1_PREPROCESSING_FLOW.md).

## Направление 1. Создание и просмотр сессий в контексте ноды

Статус первого блока: **согласовано владельцем 2026-09-04**.

Инвариант: если в Bria показаны или запущены сессии, конкретная текущая нода
уже выбрана. Состояния с общими сессиями без выбранной ноды не существует,
независимо от количества подключённых нод.

| Шаг | Текущая трактовка целевого поведения |
|---|---|
| 1. Первый запуск | Текущей автоматически становится нода-координатор. Открываются только её сессии; отдельный обязательный стартовый выбор ноды не показывается. |
| 2. Повторный запуск | Восстанавливается последняя выбранная нода и набор открытых на ней сессий. Пользователь возвращается в прежний нодовый контекст; промежуточного состояния без выбранной ноды нет. |
| 3. Область видимости | Переход в раздел сессий всегда показывает только сессии выбранной ноды. Списки активных и архивных сессий разных нод не объединяются. |
| 4. Доступ к нодам | Раздел `Ноды` доступен всегда. В активной карточке строка действий следует эталону `bria-legacy`: `➕ Новая`, `Ноды`, `≡ Меню`. Через `Меню → Статус` доступны те же кнопки нод и то же переключение, но текст экрана содержит таблицу квот CLI. |

После выбора другой ноды она становится текущей и открывается её собственный
набор сессий. Кнопка `➕ Новая` создаёт сессию только на текущей ноде: для
создания на другой ноде пользователь сначала переключает ноду.

Экран `Ноды` показывает зарегистрированные ноды, отмечает текущую ноду,
координатор и доступность. Экран `Статус` использует тот же набор кнопок нод и
то же переключение, но его текстовая часть начинается с таблицы расхода квот в
формате `bria-legacy`. Нода-координатор всегда находится первой в списке
независимо от порядка добавления остальных нод. Выбор доступной ноды сохраняется
и открывает её собственный набор сессий; повторный выбор текущей ноды проходит
незаметно, а недоступная нода не заменяет текущий нодовый контекст.

Переход в `Сессии` сразу открывает активную сессию текущей ноды без
дополнительного нажатия. Если активная сессия удалена или закрыта, активной
становится предыдущая активная из истории этой ноды. Пустой экран с кнопкой
`➕ Новая` допустима только тогда, когда на текущей ноде сессий нет вообще.

Квоты собираются вне пользовательского callback-пути и читаются экраном из
кэша. Codex опрашивается через ограниченный JSON-RPC `account/rateLimits/read`.
Claude опрашивается через `/usage` в отдельной изолированной tmux-сессии,
которая принадлежит процессу Bria и удаляется при его штатной остановке; для
первичной инициализации этой сессии используется один минимальный warm-up
запрос, как в `bria-legacy`. Ошибка опроса не задерживает открытие `Статуса` и
оставляет для исполнителя прочерки до следующего успешного сбора.

Telegram принимает и отправляет только нода-координатор. Остальные ноды не
подключаются к Telegram и не могут автоматически принять эту роль. Поэтому при
недоступном координаторе весь Telegram-интерфейс Bria недоступен; переключение
ноды через него невозможно до восстановления координатора.

При повторном запуске доступная последняя выбранная нода восстанавливается
вместе с её открытыми сессиями. Если она недоступна, но координатор доступен,
текущей автоматически становится нода-координатор и открываются её сессии.

Если выбранная рабочая нода становится недоступна уже во время работы,
поведение зависит от открытого экрана:

- на экране `Ноды` текущей автоматически становится доступная
  нода-координатор;
- из активной карточки сессии недоступной ноды пользователь переводится на
  экран `Ноды`, без автоматического открытия карточки координатора.

В пределах выбранной ноды применяются согласованные ниже шаги: выбор включённого
backend при необходимости, динамический выбор или создание директории,
опциональная рекомендация архивной сессии и затем открытие новой сессии.

### Согласованный блок: вход в создание и backend

| Шаг | Согласованное целевое поведение |
|---|---|
| 1. `➕ Новая` | Создание сразу привязывается к текущей ноде; отдельного выбора ноды внутри flow нет. |
| 2. Недоступная нода | Новая сессия и черновик на другой ноде не создаются. Сразу открывается меню `Ноды` для переключения. |
| 3. Backend | Учитываются backend только текущей ноды. Один включённый выбирается автоматически; при нескольких применяется настроенный выбор либо показывается меню; неустановленный ведёт к установке, установленный выключенный можно активировать. |
| 4. Повторное нажатие | Повторное нажатие `➕ Новая` продолжает тот же черновик и не создаёт видимого дубля. |

### Согласованный блок: выбор директории

| Шаг | Согласованное целевое поведение |
|---|---|
| 1. Вход | Этап пропускается только при явно заданной для текущей ноды директории по умолчанию. Если она недоступна, открывается обычный выбор. |
| 2. Навигация | Показываются только разрешённые корни текущей ноды. Папки открываются динамической клавиатурой, списки перелистываются кнопками `◀` и `▶`, а кнопка `..` поднимает на один уровень выше и отсутствует в списке корней. |
| 3. Выбор | Нажатие папки открывает её; отдельная кнопка `Выбрать` фиксирует текущую директорию. |
| 4. Создание папки | После ввода имени создаётся и открывается дочерняя папка. Она не выбирается автоматически: можно продолжить навигацию либо нажать `Выбрать`. |

### Согласованный блок: рекомендации архива

| Шаг | Согласованное целевое поведение |
|---|---|
| 1. Настройка выключена | После выбора директории новая сессия создаётся сразу. Рекомендации по умолчанию выключены. |
| 2. Настройка включена | Без заметной задержки ищутся только архивные сессии текущей ноды с выбранными backend и директорией. |
| 3. Экран | Рекомендации упорядочены по актуальности, перелистываются кнопками `◀` и `▶`; кнопка `➕ Новая` продолжает создание новой сессии. |
| 4. Выбор | Выбор рекомендации отменяет создание и выполняет точное продолжение архивной сессии. Повторное нажатие не запускает второе продолжение и проходит незаметно. |

### Согласованный блок: завершение создания

| Шаг | Согласованное целевое поведение |
|---|---|
| 1. Параметры | Новая сессия создаётся только на зафиксированных текущей ноде, backend и директории. |
| 2. Запуск | Карточка открывается сразу, backend запускается в фоне, а сообщения во время запуска надёжно принимаются в очередь. |
| 3. Активация | Новая сессия становится активной; предыдущая активная сессия продолжает работу в фоне. |
| 4. Карточка | Сохраняется контекст текущей ноды, а переключатели содержат только её открытые сессии. |

### Согласованный блок: выход и черновик

Черновик создания принципиально не сохраняется: ни между экранами после выхода
из flow, ни между нодами, ни после перезапуска Bria.

| Шаг | Согласованное целевое поведение |
|---|---|
| 1. `Назад` | Возвращает только по реально показанным этапам; из первого этапа закрывает создание и возвращает к сессиям текущей ноды. |
| 2. `Меню` | Закрывает flow и удаляет черновик создания. |
| 3. Переключение ноды | Закрывает flow и удаляет черновик прежней ноды, затем показывает сессии выбранной ноды. Параметры между нодами не смешиваются. |
| 4. Повторный вход | После любого выхода, переключения ноды или перезапуска `➕ Новая` начинает весь flow заново. Только повторное нажатие внутри ещё открытого flow продолжает текущий несохранённый черновик и не создаёт дубль. |

### Согласованный блок: отказ во время создания

| Событие | Согласованное целевое поведение |
|---|---|
| Нода отключилась | Черновик удаляется и автоматически открывается `Ноды`; создание не переносится на другую ноду. |
| Backend выключился | Если нода доступна, flow возвращается к выбору backend, а директория выбирается заново. |
| Директория исчезла | Сессия не создаётся; показывается ошибка и браузер разрешённых корней текущей ноды. |
| Backend не запустился | Ложной открытой сессии не остаётся. Пользователь остаётся на текущей ноде и может заново пройти flow через `➕ Новая`. |

### Согласованный блок: активная сессия каждой ноды

| Шаг | Согласованное целевое поведение |
|---|---|
| 1. Запоминание | Каждая нода отдельно хранит упорядоченную историю активных сессий, чтобы после удаления текущей восстановить предыдущую. |
| 2. Переключение ноды | После выбора ноды открывается её последняя активная сессия. |
| 3. Вход в `Сессии` | Активная сессия открывается сразу. Если текущая активная удалена, открывается предыдущая активная; активной сессии нет только при полном отсутствии сессий на ноде. |
| 4. Скрытая нода | Её сессии исчезают из текущего интерфейса, но продолжают работать в фоне и восстанавливаются в интерфейсе при возврате на ноду. |

### Согласованный блок: настройки пропуска этапов

| Настройка | Согласованное целевое поведение |
|---|---|
| Область | Настройки создания явно относятся к текущей ноде. |
| Backend по умолчанию | Если выбранный backend установлен и включён, этап пропускается; иначе открывается обычный выбор. |
| Директория по умолчанию | Если путь доступен в разрешённых корнях текущей ноды, этап пропускается; иначе открывается браузер директорий. |
| Сброс | Удаляет значения только текущей ноды и не меняет настройки остальных нод. |

Рекомендации архива остаются отдельной общей настройкой и по умолчанию
выключены.

## Направление 2. Автоматически открытая новая сессия

| Шаг | Текущая трактовка целевого поведения |
|---|---|
| 1. Настройка | Функция включается отдельной настройкой и по умолчанию выключена. Она действует в контексте конкретной открытой ноды. |
| 2. Директория | Для этой ноды заранее открывается пустая сессия `➕ Новая` в её наиболее популярной директории. Популярность между разными нодами не смешивается. |
| 3. Стабильность | Если после открытия пустой сессии наиболее популярная директория изменилась, уже открытая сессия не переносится и не пересоздаётся. |
| 4. Замещение | Как только в ожидающей сессии появляется первый контекст, она становится обычной сессией. Следующая пустая сессия открывается в директории, которая наиболее популярна для этой ноды уже в этот момент. |

Выбранные детали реализации 2026-09-06:

- «Ожидающая сессия» — отдельный сохраняемый переключатель, по умолчанию OFF.
  Прежнее «Продолжать существующую» не управляло поведением и скрыто, его
  сохранённое значение не переносится в новую настройку.
- Подготовка запускает реальный CLI в фоне для выбранной ноды. Существующая
  активная сессия не переключается; новая выбирается только при отсутствии
  активной. Пустая подготовленная сессия помечена `➕ Новая`.
- Первый надёжно сохранённый пользовательский запрос (в том числе ожидающий
  или ошибочный) запускает подготовку следующей. Повторные события одного
  запроса не создают дубликаты. При выключении новые сессии не создаются;
  уже созданная не удаляется автоматически.
- Популярность — число сохранённых сессий этой ноды, без неиспользованных
  автоматических заготовок; равенство разрешают свежесть создания и путь.
  CLI: включённый нодовый default, затем последний использованный включённый,
  затем первый включённый. Без истории: нодовая default-папка, затем home.
- Изменение популярности не переносит существующую заготовку. Неизвестный
  результат запуска не повторяется автоматически. Ошибка доступна в настройках
  создания без сырых провайдерских сообщений; повтор — при следующем входе.
