# systemd deployment

The production Go daemon runs as one `bria node` process per host. The
legacy Python `hub` and `agent` units are not used.

Linux hosts that execute provider agents should use the separate
`bria-runner.service` and `bria-node-isolated.conf`; see
`docs/linux-runner-isolation.md`. The single-user unit below remains valid for
trusted hosts and backwards compatibility, but does not isolate a hostile
backend from node-control secrets.

The supplied unit expects:

- `/opt/bria/current/bria` — the architecture-specific Go binary;
- `/etc/bria/node.json` — the node configuration generated by
  `bria cluster init`;
- `/var/lib/bria` — node state owned by the `bria` service user;
- optionally `/etc/bria/proxy.env` — a root-owned `0600` file containing
  process-local proxy variables, never global routing changes.

Bootstrap the first node before enabling the service. Keep Raft on loopback
for a single-node smoke deployment; expose it only after peer mTLS, routing,
and firewall rules have been reviewed.

```bash
sudo useradd --system --home-dir /var/lib/bria --shell /usr/sbin/nologin bria
sudo install -d -o bria -g bria -m 0700 /var/lib/bria
sudo install -d -o root -g bria -m 0750 /etc/bria
sudo install -d -o root -g root -m 0755 /opt/bria/releases

sudo -u bria /opt/bria/current/bria cluster init \
  --cluster-id personal \
  --node-id host-id \
  --node-name "Host name" \
  --owner-user-id 123456789 \
  --data-dir /var/lib/bria \
  --config /var/lib/bria/node.json \
  --raft-bind 127.0.0.1:7946 \
  --raft-advertise 127.0.0.1:7946

sudo mv /var/lib/bria/node.json /etc/bria/node.json
sudo chown root:bria /etc/bria/node.json
sudo chmod 0640 /etc/bria/node.json
sudo install -o root -g root -m 0644 \
  deploy/systemd/bria-node.service \
  /etc/systemd/system/bria-node.service
sudo systemctl daemon-reload
sudo systemctl enable --now bria-node.service
```

Official release archives can be installed atomically with
`sudo scripts/install-linux.sh bria_VERSION_linux_ARCH.tar.gz`. The installer
verifies that the extracted binary starts, creates an immutable release
directory, and switches `/opt/bria/current` without deleting the previous
release. Rollback is an explicit symlink switch to that retained directory.
The installer gives the unprivileged `bria` service account ownership only of
`/opt/bria`; the unit allows writes only there and in `/var/lib/bria`. This is
required for signed self-updates and does not grant host administration. Hosts
installed with an older unit need this one-time ownership and unit migration
before Telegram rolling updates can activate a release.

Do not create the configured Telegram token file until this node is intended
to be the only poller for that bot token. Telegram permits only one active
`getUpdates` consumer.

For monitoring, run `bria node probe --config /etc/bria/node.json` as the
`bria` service user. It exits non-zero if the process cannot authenticate
to node control or the node has no current Raft leader. Use `--health-only`
only for a separate liveness check; it intentionally remains successful while
the node is alive but isolated from quorum.

For a private multi-node deployment, add a host-specific systemd drop-in with
`IPAddressDeny=any` and narrow `IPAddressAllow=` entries for loopback and each
peer's private address. This filter applies only to the Bria cgroup and
does not alter host routes, DNS, firewall rules, VPNs, or proxy processes.
Add the Telegram proxy endpoint to the allowlist before enabling its token.

On cloud networks with one-to-one NAT, a private-address bind may still be
reachable through the public NAT address. Install the supplied
`bria-raft-firewall` helper and unit with a root-owned `0600`
`/etc/bria/network.env` containing `BRIA_RAFT_CIDR`. The helper adds
idempotent INPUT rules scoped only to `BRIA_PRIVATE_PORTS` (Raft 7946,
node-control 7947, and enrollment 7948 by default); it does not change routes,
DNS, VPNs, proxies, or rules for
existing services. Loopback remains allowed so a private socket proxy can
reach an SSH reverse-forward without exposing it on another interface. Make
the node unit require the firewall unit in its
host-specific cluster drop-in. A relay host can use, for example,
`BRIA_PRIVATE_PORTS="7946 7947 7948 17946 17947 18081"` to protect Raft, node
control, the Android relays,
and a process-local Telegram proxy with the same private-network boundary.

`KillMode=process` lets tmux sessions survive a daemon restart. The default
sandbox only permits writes under `/var/lib/bria`; add narrowly scoped
`ReadWritePaths=` entries for project roots before enabling session execution.
Do not weaken the host's global proxy, DNS, routing, or firewall settings.
